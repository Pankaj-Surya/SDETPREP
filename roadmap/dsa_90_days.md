## **2. Daily study structure**

We will spend approximately 60 minutes every day.

| Time   | Activity                            |
| ------ | ----------------------------------- |
| 10 min | Understand the concept              |
| 15 min | Learn the approach with examples    |
| 25 min | Solve the coding problem            |
| 10 min | Complexity, edge cases and revision |

**Important rules:**

1. First try solving the problem yourself.
2. Don't immediately look at the solution.
3. Understand brute force before optimized solutions.
4. Always explain why your approach works.
5. Write time and space complexity.
6. Revisit difficult problems after a few days.

## **5. How I will teach each day**

We will follow one consistent learning template.

For example, Day 10 – Two Sum:

1. **Problem statement:** Understand what the interviewer is asking.
2. **Example:** Input `[2, 7, 11, 15]`, target `9`.
3. **Brute-force approach:** Explain the nested loop.
4. **Optimized approach:** Solve using HashMap.
5. **JavaScript/TypeScript implementation:** Write clean code.
6. **Dry run:** Execute the code step by step.
7. **Complexity:** Explain time and space complexity.
8. **Edge cases:** Empty array, duplicates, negative values.
9. **Interview questions:** Follow-up questions an interviewer might ask.
10. **Practice:** One additional variation.

This way, we learn problem-solving rather than memorizing code.
